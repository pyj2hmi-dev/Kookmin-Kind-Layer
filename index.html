Problem Definition

정보는 있지만,
행동은 막힌다.

사용자는 정보를 몰라서만 멈추지 않습니다. 어려운 문구, 늦게 보이는 준비물, 제출 실수에 대한 불안 때문에 다음 행동을 선택하지 못합니다.

01

행정 문구가 어렵다

긴 문장과 전문 용어 때문에 지금 할 일을 바로 파악하기 어렵습니다.

용어 장벽
02

준비물을 너무 늦게 안다

마지막 단계에서야 서류나 인증 수단 부족을 발견합니다.

서류 누락
03

오류 후 해결책이 모호하다

제출 실패나 인증 오류 뒤 무엇을 고쳐야 하는지 알기 어렵습니다.

루핑
04

실수에 대한 불안이 크다

잘못 누르면 손해 볼 것 같은 압박이 제출 직전 이탈로 이어집니다.

Solution

길안내.

행정을 대신 처리하는 서비스가 아니라, 기존 화면 위에서 사용자가 이해하고 행동할 수 있게 돕는 보조 레이어입니다.

💬

✅

필요 서류, 인증 수단, 선행 조건을 먼저 보여줍니다.

📍

다음 행동 안내

눌러야 할 곳과 확인 항목을 1~3단계로 좁힙니다.

Process

화면을 읽고,
상태를 보고,
행동으로 바꾼다.

하나의 챗봇이 아니라, 현재 화면과 사용자 행동 신호를 읽고 적절한 안내 방식으로 변환하는 레이어 구조입니다.

1
입력 인식화면 텍스트, 버튼, 사용자 입력, 행동 로그 수집
2
맥락 해석현재 화면이 어느 업무 단계인지 추정
3
개입 판단혼란·불안·답답함·피로 신호와 환경 마찰 결합
4
행동 유도쉬운 설명, 체크리스트, 하이라이트, TTS 출력
Layer 01

Client-side Overlay

기존 시스템을 수정하지 않고 화면 위에 안내를 표시합니다.

Layer 02

Rule-based Guide

반복 화면과 병목 구간은 로컬 룰로 빠르게 안내합니다.

Layer 03

LLM Fallback

예상 밖 질문, 오류, 절차 이탈 상황에서만 AI를 호출합니다.

Layer 04

Risk Boundary

자격 판정, 법적 해석, 제출 대행은 제외합니다.

Risk Review

할 수 있는 것과
하지 않는 것을 나눈다.

공공행정 AI는 기능보다 경계가 중요합니다. 사용자를 돕되, 공식 판단처럼 보이는 순간 책임 문제가 커집니다.

AI는 자격을 판정하지 않는다

수급 가능 여부와 행정 판단은 공식 기관의 영역으로 남기고, AI는 확인 포인트만 제공합니다.

기관 시스템을 먼저 건드리지 않는다

초기 MVP는 직접 연동보다 미러 화면과 오버레이 데모로 보안·권한 리스크를 줄입니다.

확정 안내 대신 검증 포인트를 준다

“이쪽입니다”가 아니라 “이 항목이 보이면 맞는 경로입니다”로 안내합니다.

개인정보 처리는 최소화한다

민감 정보 원문 저장보다 로컬 처리, TTL, 익명화 로그를 우선 검토합니다.
